# v0.4: Touchscreen setup for the Raspberry Pi 4B

**Target deployment: 12 December 2026.** The user confirmed v0.3 on the physical panel, including QR downloads; the official Editor compiled it after the keyboard page was renamed to `keyboard`. This release keeps that name and stays on a separate candidate branch. Keep the actual working v0.3 HMI/TFT, Pi checkout, units and SQLite database for rollback. The older v0.3 archive in Git predates the on-device naming fix.

## What you can do at the station

| Page | Operation |
| --- | --- |
| **Station → WLAN** | Search, page through available networks, read signal percentage and security, select a network, connect. Enter the password on the native keyboard. It shows asterisks and clears working text on submit/cancel/exit. The result shows the SSID and IPv4 address. |
| **Station → Drucker** | Change IPv4 and TCP port (saved individually); test TCP without sending print data; send a clearly marked simulated test receipt. A TCP success is not a printer-status or physical print acknowledgment. |
| **Station → Beleg** | Switch graphical/text header, change pre-cut feed by 5 mm (0–100 mm) and choose density. **Druckervorgabe** sends no extra command. Enable Hell/Dunkel only where the exact printer model supports Epson GS ( K function 49 with values 255/1. |
| **Station → System & Display** | Adjust brightness in 10% steps; cycle standby Off/30/60/120/300/600 s. Native touch wakes the panel. Read Pi model and display/UART details. |
| **System → Neustart / Ausschalten** | Separate confirmation page, 20-second limit. The Pi refuses control until explicitly enabled and authorized by logind. Ongoing print, printer test or Wi-Fi work blocks the action. |

Supported Wi-Fi: visible open, WPA/WPA2-Personal, WPA3-SAE, and WPA2/3 transition networks. Use 8–63 printable ASCII characters or a 64-character hexadecimal WPA/WPA2 key. Hidden SSIDs, captive-portal sign-in, WEP and enterprise/802.1X provisioning are outside this release; configure needed profiles separately in NetworkManager. The available list includes an enterprise label but does not attempt to join it. Use a network that permits phone-to-Pi traffic: some guest networks isolate clients even when both devices have Internet.

The Pi uses NetworkManager on `wlan0` by default. No network is needed to use the touchscreen. A separate worker handles scans, activation and status calls; printer I/O has its own worker. On a successful activation with IPv4, NetworkManager saves the profile for boot-time reconnection. On failure the app tries to reactivate the previous profile. Passwords are passed over the local system bus, never in command arguments, app settings files or application logs. NetworkManager stores the successful profile and credential in its normal system store. Nextion UART carries the submitted credential locally in clear text, so do not leave serial recording/debug instrumentation attached while entering it.

Use `--auto-report-url` (enabled by the example service): QR links use the Wi-Fi interface's current IPv4, refresh after it changes, and disappear when disconnected. `--report-url` still supports a fixed URL when auto mode is off. PDF requests stay on the LAN. Printer traffic uses its independently configured endpoint (existing default `169.254.223.252:9100`); don't put the LAN on the same subnet as a separately configured Ethernet printer link.

The web admin and panel use the existing `~/.config/rc-printstation/receipt.json` as the same Unix user. The web form edits the same three receipt preferences. Existing graphics/feed values are preserved. Updates merge keys atomically under a lock. No database schema migration is needed. Keep the admin site on loopback; use your existing SSH tunnel, e.g. `ssh -L 8081:127.0.0.1:8081 YOUR_PI`.

## Bench install and autostart

1. Back up the **actual deployed** v0.3 files (including the compiled TFT with the renamed keyboard), both units, and database. Inspect the existing units with `systemctl cat rc-printstation.service rc-printstation-admin.service`. Record the service user, working directory, and `--db` path. Work in a separate checkout with a separate test database.
2. Install Pi dependencies: `sudo apt install python3-serial python3-reportlab python3-dbus network-manager`. Confirm `NetworkManager.service` is running, that `nmcli device status` shows the Wi-Fi device it manages, and that the configured service user can use `/dev/serial0` (dialout). Do not change the working Ethernet link or disable existing services merely to validate this candidate.
3. Open the v0.4 HMI in **official Nextion Editor 1.68.2** and compile as a separate copy. Follow [validation](../hmi/VALIDATION-v04.md), then bench-test with `/usr/bin/python3 native_ui.py --port /dev/serial0 --baud 115200 --auto-report-url --db /tmp/rc-v04-test.sqlite3` as the station user. Stop the previous process that owns the UART first. The backend checks the correct model and protocol 4 before writing settings.
4. Review NetworkManager permissions **in the service context**. Scanning/activation/profile storage may require the administrator to allow the station user's `org.freedesktop.NetworkManager.wifi.scan`, `org.freedesktop.NetworkManager.network-control` and `org.freedesktop.NetworkManager.settings.modify.system` actions, depending on the Pi's policies. The last action can modify system network profiles; grant it only to the chosen trusted account. Keep logind power authorization separate. Start without power enabled; after checking its behavior, give the station account only approved logind reboot/power-off actions and opt in with `--enable-local-power`. Multiple sessions or inhibitors may cause a safe refusal; don't disable those checks.
5. `bash tools/install_services.sh --render /tmp/rc-v04-units --db /tmp/rc-v04-test.sqlite3` previews the units without installing. The installer keeps the same names, runs as the current non-root user, verifies dependencies/units, starts neither service, uses restart-on-failure and avoids waiting for network-online. After bench acceptance, stop the old services and run `bash tools/install_services.sh --replace --db /ABSOLUTE/PATH/reports.sqlite3` with the verified database path. Existing unit files are backed up; a live unit or missing dependencies prevent installation. Inspect the result, then explicitly start both units. Do not run a manual UART client and the service together.
6. If rollback is needed, stop v0.4, restore the saved units and matching v0.3 backend/TFT, run `sudo systemctl daemon-reload` and restart the two services. Keep the existing Wi-Fi profiles unless a failed bench enrollment needs cleanup; v0.4 does not delete pre-existing profiles.

Wi-Fi manager reference: [NetworkManager activation API](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.html), [wireless scanning](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.Wireless.html). Printer density: [Epson model-specific GS ( K reference](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/gs_lparen_ck_fn49.html). Power authorization: [systemd-logind](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.login1.html).

## Saved Wi-Fi and temporary hotspot (backend update)
Scanned networks with compatible saved NetworkManager profiles have a [gesp.] suffix and connect with the existing profile rather than requesting a password. Select FMI Hotspot starten in the WLAN list (at the end of results, or immediately before a scan), then confirm. The temporary open AP uses 10.42.0.1/24 with no password. It replaces client mode on wlan0; the SSH session may disconnect. NetworkManager shared mode supplies DHCP on WLAN and may share a routed uplink if present; the dedicated printer Ethernet interface is unchanged. For AP use grant the trusted station user org.freedesktop.NetworkManager.wifi.share.open if required. To return to client mode select Hotspot beenden, then scan and connect to a saved network if it does not reconnect automatically. The AP is volatile and does not start automatically on reboot; if the backend alone restarts, the existing AP can remain active. No HMI update is needed. Hardware validation pending.
