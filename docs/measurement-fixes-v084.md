## Operator behavior

- A real USB cable row has designation `Kabel`, value `Gut`, an empty unit and its own verdict. A real CP437 printer report uses `Kabelprüfung  Gut`. Raw tokens, units and original verdicts are retained. Cable text is handled separately from numeric readings. Unknown or missing status stays open even with an overall pass. An observed but unexported cable indication can be recorded in guided examination remarks. Remarks remain operator observations and cannot supply a missing tester measurement.
- At review, the HDMI and browser show the selected guide class and imported test type. USB labels are transmitted. An RS232 cable line identifies a cable procedure. Positive RS232 signatures can suggest Class I or II and are marked **abgeleitet / inferred**. An ambiguous record stays explicitly unknown. The paired records support these signatures by slot, date and matching values, with the captured insulation limits as additional evidence. The station does not join records or infer an appliance class from slot number or missing rows. The Class III guide continues to accept the Class II tester programme as documented for that procedure.
- If a mismatch appears, **Andere Messung wählen** clears the selection and **Abbrechen** returns to the previous step. **Geprüfte Prüfart übernehmen** requires verification of an explicitly transmitted procedure. **Ohne Freigabe dokumentieren** preserves the discrepancy without adopting the imported class. Both save the original verdict and data provenance, preserve the previous guide observations as audit data, and require a fresh full examination before release. Setup, visual, functional, result and voltage confirmations from the other procedure do not transfer to this record. The responsible examiner still decides release. Inferred classifications cannot be adopted.
- Completeness is assessed using the applicable procedure. Class I accepts IPE or IEA. Class II uses IB/IBer or IEA. Cable requires RPE, RISO and an explicit cable indication. If an individual failure in an earlier stage explains the missing later readings, the details say they were not recorded after the failure. Missing readings before or at the failing step and genuine missing readings on a pass still raise warnings. See [ST 725 Swiss manual, rev. 12/2021, §§7.3–7.6 and 9.1–9.3](https://www.ottofischer.ch/pim/c4c9c5b2-be92-425c-aba6-e7ed19ab4a17/0249_P_0519147.pdf).
- The official receipt table uses the accepted Epson 42-column text mode. Readings and supplied limits share a row, with long values and original individual verdicts continued within their columns. USB limits remain empty because the tester does not send them. Branding, overall verdict raster, footer, paper feed and cutter keep their previous layout. Corrected completeness and mismatch annotations appear in the existing reporting areas. The PDF retains its compact report layout.

## Reproduce the tests and focused previews

- Run `python -m unittest discover -s tests` with the existing venv dependencies. Run `QT_QPA_PLATFORM=offscreen /usr/bin/python3 -m unittest discover -s tests -p 'test_hdmi*'` with system Qt. Setting `FMI_V084_HDMI_PREVIEW` writes one warning screenshot during the interaction test.
- Start `PYTHONPATH=.:tests python tests/browser/fixture_server.py` locally, open `http://127.0.0.1:18191` and run `tests/browser/operator_flow.js` in Chromium. Inspect `window.v082Result` for the interaction result. The optional Qt WebEngine driver captures two focused review screens in German and English.
- Run `python tools/render_v084_previews.py OUTPUT` with Pillow, the legacy HMI preview dependencies and DejaVu fonts. The package contains six receipt images and three PDF examples. The English cable failure is clearly labeled synthetic. Receipt text uses a monospace preview font and actual emitted raster blocks.
