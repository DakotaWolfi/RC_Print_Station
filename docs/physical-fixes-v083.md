# FMI Printstation v0.8.3 bench candidate

This candidate builds on the v0.8.2 physical feedback in [issue #3](https://github.com/DakotaWolfi/RC_Print_Station/issues/3). Ten checks were reported successful for that baseline. Keypad and scrolling acceptance, a possible 90° cold-boot inversion and the independent operator walkthrough were still open. The v0.8.3 verification below uses development fixtures. Physical acceptance remains pending.

## Bench installation and rollback

1. Leave the deployed checkout and storage alone. On a separate bench image, record the previous checkout and unit definitions. Take a consistent SQLite backup (use SQLite's backup command or stop the bench services before copying), including the reports and personality databases. Back up private service environment, configuration, autostart files and the service user's `~/.config/rc-printstation/`.
2. Check out `feature/physical-fixes-v083` separately. Review the [v0.8.2 network and service guide](reliability-usability-v082.md) and [bench hardware guide](usability-web-v081.md) for platform-specific prerequisites. Keep the same service user, printer endpoint, serial paths, NetworkManager profiles and private web configuration. Production target remains Orange Pi Zero 3 (1 GB).
3. Render the units before installing them. This example uses a copied database and a Wayland session on a Pi 4. For an Orange Pi Zero 3 use `--board zero3`. For a tablet-only setup use `--mode headless --web`. The existing `--touch` option can point to a stable `/dev/input/by-path/…` event symlink. Review the rendered units before an explicit bench installation.

```sh
tools/install_multi_display.sh --board pi4 --mode hdmi --backend wayland \
  --connector HDMI-A-1 --web --db /home/pi/bench.sqlite3 --render /tmp/fmi-v083
```

4. Keep the bench GPIO RX values confirmed for its adapter and the existing USB CSV device configuration. Keep the trusted operator LAN and administrator credential, including the existing protected hotspot policy. The whitelist stays optional. No changes to production URLs, network interfaces or Nextion firmware are required. The local printer fallback remains `169.254.25.23:9100`.
5. To roll back, stop the bench services, restore the previous unit definitions, autostart launcher and configuration pointing to the prior checkout, then restart them. Keep a separate copy of the candidate database and reports. No database schema migration is required. New reports add optional JSON provenance fields and published PDFs add an internal ID in the existing JSON payload. Calibrations are stored separately from the database. The old branch ignores the new touchscreen profile. A pre-upgrade backup restores the exact earlier state. Copying it back also discards any later writes from the active database, so retain the newer copy.

## Frontend recovery and new measurements

During an active guide, import or review, a live operator frontend retains control. A second display can see that the examination is occupied. Use **Anzeige wechseln** to release control, then confirm **An dieser Anzeige fortsetzen** on the other display. If the frontend closes or loses its connection, wait at least 20 seconds after its last state poll. Recheck the actual BENNING display and appliance setup before confirming resume. A complete core restart returns an unfinished examination to entry with a recheck notice. Printed jobs and safety decisions are never replayed during handoff or recovery.

A valid but shortened full USB memory export (including a correctly framed header-only export) is held for explicit confirmation. Confirm **Speicher-Reset bestätigen** only after verifying that the memory really was cleared and the export was completed. A new transfer invalidates the held frame. The confirmation updates the live slot list and keeps all imported history and existing reports. An RS232 report does not provide a complete memory inventory. It therefore does not confirm a reset by itself. A changed payload under the same slot can become a fresh measurement. A byte-equivalent reading cannot be distinguished from a resend by the receiver. Select it and affirm the same-reading prompt only if you personally know a new test was performed. An old report always reprints its saved snapshot. BENNING serial stays receive-only.

Ordinary PASS/FAIL remain directly selectable. **Meldung oder Unsicherheit** opens the observed messages, including Lo LOAD, flashing I LEAK, HIGH LOAD and uncertain results. The guide retains the corresponding checks and asks the operator to verify the actual tester indication. Connections, button symbols and safety branches follow the existing [workflow traceability](benning-guided-workflows.md) and the [BENNING ST 725 CH manual, rev. 12/2021, §§8.4, 9.1–9.3 and 10](https://www.benning.de/files/benning/global_content/downloads/instruction_manuals/benning_st725_ch_version_manual.pdf).

## Touch, downloads and novelty receipts

- Select **Einstellungen → Anzeige → Touchscreen kalibrieren** on HDMI. The station user needs `python3-evdev` and access to the selected touchscreen's event node. Grant access to that device through the kiosk session ACL or a narrowly scoped device rule. A touchscreen needs a stable udev identity and raw absolute input axes. The active calibration path uses one single-touch or type-B device per kiosk, and forwards one contact. Other touchscreens can still use the platform's pointer mapping.
- Tap all five targets, then confirm the preview within 15 seconds. Escape, cancellation, disconnect or timeout discards an unsaved profile. The saved affine transform maps raw data into the physical viewport, while Qt applies the inverse of the configured UI rotation once. Keep the compositor transform fixed. A saved profile is scoped by display and device and reapplied when the device returns. If touch is unusable, use a mouse/keyboard to reset the profile in Display settings, or close the kiosk and move aside `~/.config/rc-printstation/touchscreen.json` before relaunching. Leave the previous file available if it is needed for diagnosis.
- Start a drag anywhere in scrollable content. Once it exceeds the movement threshold it scrolls without activating the button under the start point. Wheel and scrollbar remain available.
- Open **PDF / QR-Code** on the report. HDMI **PDF speichern** shows the full local destination and asks for confirmation. The default directory is the kiosk user's Downloads folder. Set `FMI_PDF_EXPORT_DIR` in the kiosk launcher environment for another writable destination on a local filesystem with hard-link support. Repeat saves receive a numeric suffix rather than overwriting. The browser has independent **PDF herunterladen** and **QR-Code anzeigen** actions. The filename is `FMI-YYYY-MM-DD-examination-Rrecord.pdf`, using the original examination date when present, otherwise the report date. The station connection QR remains separate. Treat all PDF tokens as private.
- On the wolf screen select **Spassbeleg** and a design. The confirmation follows a preview of the exact 504-dot monochrome raster. The three designs, in German and English, use the existing illustrated mascot. Each job ends with at least 45 mm of blank feed, or the configured feed if larger, and one final cutter command. The old novelty job sent plain text and roughly 15 mm of feed. This was a concrete difference in the byte stream. The physical cause of the earlier cutoff remains unverified. The new byte ordering follows the Epson [raster command](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/gs_lv_0.html) and [cutter command](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/gs_cv.html). The official receipt uses its existing design and feed settings.

## Reproducible development checks

- Run `python -m unittest discover -s tests` in a project venv with the existing report and legacy HMI dependencies. 116 cases were discovered, 101 passed and 15 skipped. The 14 Qt skips ran separately and passed using `QT_QPA_PLATFORM=offscreen /usr/bin/python3 -m unittest discover -s tests -p 'test_hdmi*'`. One AF_UNIX end-to-end test could not bind its socket in the workspace. The individual core and gateway tests use an injected transport.
- The Chromium/Qt WebEngine run completed an anonymous guided examination with a fixture RS232 import. It checked local administrator authentication, the attachment, QR toggle, wolf/pet count and achievements, and captured one official and one novelty print. It rendered the changed browser report/novelty screens in German and English across the selected phone and tablet sizes. The browser test shell routes the real PDF response through the fixture origin and reads it after the click, bypassing the shell's native file chooser. Production CSP and PDF listener origins are unchanged.
- Render the focused native previews at 480×800, 800×480, 600×1024 and 1024×600 with `QT_QPA_PLATFORM=offscreen /usr/bin/python3 tools/render_v083_previews.py OUTPUT`. Generate the thermal raster assets with `python tools/generate_novelty.py` and Pillow.
- For the browser fixture, use `PYTHONPATH=.:tests python tests/browser/fixture_server.py`. From a fresh Chromium tab open `http://127.0.0.1:18191`, execute `tests/browser/operator_flow.js` and inspect `window.v082Result`. The optional `tests/browser/qtwebengine_driver.py` runs that interaction script and captures the layouts. Fixture ports and credentials are for development only.

## Physical acceptance checklist

- [ ] Cold boot at the saved 90° setting. Tap all four corners, run and save calibration, reboot, then unplug/reconnect HDMI and USB touch separately. Record the connector, backend and touch device ID if any axis flips.
- [ ] Tap all digits on the physical keypad. Enter and commit `0001` and `0002`, change a printer IP on a copied configuration, scroll by finger from a button without activating it, then confirm a short tap still works.
- [ ] Start a guided examination, kill and relaunch one frontend, and confirm resume only after checking the physical tester. Keep a second live frontend open to verify it cannot take ownership early. Check that no print or safety step repeats.
- [ ] Complete the HDMI **Ohne Befund** path and an independent password-free browser examination from the station connection QR. Ask a trained operator unfamiliar with this station to find and explain the warning paths before signing off.
- [ ] Recheck known-good GPIO UART RS232 and USB CSV. Send a malformed frame followed by a valid one. Back up test memory before a deliberate clear/reuse bench sequence. Reprint a report for the old slot and compare it to its original.
- [ ] Change between eligible WLAN networks. On a phone, scan the updated connection QR and the separate PDF QR, and save the PDF. Check the filename and local HDMI destination. Confirm restricted admin actions and hotspot policy still work as configured.
- [ ] Compare the official Epson receipt with the accepted compact layout. Print each novelty design at the configured feed. Check raster contrast, complete footer, sufficient trailing blank paper and a single cut. Hold sign-off if any print is clipped.
- [ ] Check wolf pet/double tap, treats and Professional Mode. Reboot and verify preserved database and settings. Record the OS and board, physical operator, date, test outcomes, and any acceptance exceptions.
